这是两个 MCP 服务。模型 Gateway 的 /mcp 不包含 drama_* 工具。请为 Agent 添加第二个业务 MCP 连接。不能用 18082 的 /api/v1/drama/mcp 代替当前工作台地址：本部署没有在那里启用当前项目数据库。

两者使用 HTTP JSON-RPC POST，先 initialize，再 tools/list，最后 tools/call；不是旧式 GET/SSE 服务。业务连接发送 Content-Type: application/json、X-DGX-Drama-Action: explicit-user-action，协议版本 2024-11-05。Gateway 连接的认证与维护详见管理员指南。当前 LAN 配置免登录；业务服务限本机。

短剧工具通常接受 {projectId, arguments}，仅 drama_list_projects 接受空对象。projectId 从列出项目取得，episodeId 从读取项目取得；不能用 Gateway job_id 代替业务候选或资产 ID。

批量、冲突和恢复

  1. 先读取审核队列与当前版本，只对用户选中的候选操作。审核队列可能包含共享素材；检查 episodeIds、scopeKind 和 targetId。
  2. 质量批审支持 1–2000 个不重复 candidateIds，整批校验、一起保存。批量选用支持 1–64 项 selections，每项填写 targetType（entity/shot）、targetId、assetId、candidateId、expectedRevision、requestKey。一个参考槽位每批只选一张。
  3. 批量选用逐项保存，返回 complete 和 results。complete=false 表示部分失败，不能把 HTTP 200 或 isError=false 当作全部成功。成功项保留；按每项 error 定位失败。同一实体的不同槽位会逐次增加实体版本，后项须使用相应预期版本，或拆分调用并重新读取。
  4. 未知结果或网络中断：用完全相同的参数和 requestKey 重试。新一轮用户决定使用新 key。批量每项各有一个 key，不要只看顶层成功。修改过参数后须使用新 key。
  5. revision_conflict 表示内容被更新，重新读取后让用户确认是否仍要覆盖。stale_candidate 表示来源较旧，只有明确确认才传 acceptStaleCandidate=true（图片）或 acceptStale=true（视频）。工具不会自动放宽旧版本限制。
  6. 生图/视频生成仍通过任务工具提交并轮询。request accepted 不等于完成。不要因为选择参考画面就隐式提交生成，也不要因为采用视频就隐式拼接或导出。

模型层批量参数以当前 tools/list 为准，候选总数和并行数量已经允许正整数，不沿用旧指南中的 8/2 限制。实际并行受显存和运行时影响。模型切换前先 dgx_status，服务重启与模型切换是不同动作。
